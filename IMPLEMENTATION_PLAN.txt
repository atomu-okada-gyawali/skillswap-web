                        4. API CONFIGURATION
================================================================================

BASE URL
   Source: EnvironmentConfig.getBaseUrl()
   Expected: Should return http://localhost:5050/api
   File: lib/core/config/environment_config.dart

AUTHENTICATION
   Method: JWT Bearer token
   Storage: flutter_secure_storage with key 'auth_token'
   Header: Authorization: Bearer <token>
   Handled by: _AuthInterceptor in ApiClient

ERROR HANDLING
   Success response: { "success": true, "data": {...} }
   Error response: { "success": false, "message": "..." }
   Status codes: 200=success, 400=bad request, 401=unauthorized, 404=not found, 500=server error

                  6. FEATURE IMPLEMENTATION DETAILS
================================================================================

--- FEATURE: POSTS (EXPLORE SCREEN) ---
Goal: Display all skill posts, allow create/edit/delete

Screens:
   a) ExploreScreen (existing) - List all posts in grid
   b) PostDetailScreen (new) - Full post info with tags
   c) CreatePostScreen (new) - Form to create new post
   d) EditPostScreen (new) - Form to edit existing post

Flow:
   1. On load: Fetch posts from /api/posts
   2. Display in 2-column grid (existing PostCard)
   3. Tap card → Navigate to PostDetailScreen
   4. FAB (+) → Navigate to CreatePostScreen
   5. Own post: Show edit/delete options in detail screen

Create/Edit Form Fields:
   - Title (TextField, required)
   - Description (TextField, multiline, required)
   - Post Photo (ImagePicker, optional)
   - Requirements (List<String>, add/remove)
   - Tags (MultiSelect dropdown, fetch from /api/tags)
   - Location Type (Dropdown: remote/onsite/hybrid)
   - Availability (Dropdown: full-time/part-time/weekends/flexible)
   - Duration (TextField, optional, e.g., "2 hours/week")

--- FEATURE: TAGS ---
Goal: Fetch and display tags for post filtering and selection

Usage:
   a) ExploreScreen - Filter posts by tag (future)
   b) Create/Edit Post - Select multiple tags

Implementation:
   1. Fetch from /api/tags on app start
   2. Cache in Hive for offline
   3. Display as chips in forms
   4. Store tag IDs in post.tag field

--- FEATURE: PROPOSALS ---
Goal: Connect with post owners via skill exchange proposals

Screens:
   a) ProposalScreen (existing placeholder) - List proposals
   b) ProposalDetailScreen (new) - View proposal with schedules
   c) SendProposalScreen (new) - Form to send proposal

Flow:
   1. From PostDetailScreen: Tap "Send Proposal"
   2. Select skill to offer (own post or description)
   3. Add message to receiver
   4. Propose schedule (date, time, duration)
   5. Submit → POST /api/proposals
   6. View in ProposalScreen (tabs: Sent/Received)

Proposal List:
   - Sent: My proposals to others
   - Received: Others' proposals to me

Actions:
   - Pending → Accept (PATCH status: accepted)
   - Pending → Reject (PATCH status: rejected)
   - Accepted/Pending → View schedules

--- FEATURE: PROFILE ---
Goal: View and edit user profile

Screens:
   a) ProfileScreen (existing) - View own profile
   b) EditProfileScreen (new) - Edit profile form
   c) UserProfileScreen (new) - View other user's profile

Edit Profile:
   - PUT /api/auth/update-profile
   - Fields: fullName, username, profilePicture
   - Same upload method as auth

MODEL PATTERN
   - Use json_serializable annotations
   - Generate with build_runner
   - Include toJson() and fromJson() that call generated methods
   - Use factory constructors for fromJson

REPOSITORY PATTERN
   - Interface in domain/repositories/
   - Implementation in data/repositories/
   - Return Either<Failure, T> from dartz
   - Check network connectivity before remote calls
   - Cache remote data locally for offline support

PROVIDER PATTERN
   - Use ref.read() for one-time reads
   - Use ref.watch() for reactive UI
   - Use AsyncValue for async data
   - Handle loading/error states in UI

ERROR HANDLING
   - Use Failure classes from core/error/failures.dart
   - Return Left(Failure) on error
   - Return Right(success) on success
   - Show user-friendly error messages in UI
